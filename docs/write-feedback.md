# 文件写入反馈

`WriteFile` 成功写入后返回 JSON 文本，包含 `write_status`、`file_path` 和 `validation`。
工具参数和模型接入协议保持不变；依赖旧成功文本的外部消费者需要改为读取这些字段。

## 写入与校验是两件事

- `write_status: saved`：文件已保存，原内容已被覆盖。
- `validation.status: passed`：本次启用的检查通过，不保证运行结果或业务逻辑正确。
- `failed`：发现代码或 JSON 问题，`checks[].diagnostics` 提供行、列、编号和说明。
- `skipped`：文件类型不支持或超过大小限制，不表示检查通过。
- `checker_error`：检查器不可用、超时、输出异常，不等同于代码有错。

保存成功时 `ToolResult.is_error` 仍为 false；调用方必须独立读取校验状态。
写入失败或路径越界仍按原方式返回工具错误。校验失败不自动回滚文件，也不自动修改内容。

## 支持范围

- `.py`：Python 编译检查，不执行或导入目标代码，不生成字节码文件。
- `.json`：解析完整 JSON，拒绝 NaN、Infinity 等非标准常量。
- 其他后缀：明确跳过。
- 自动校验的文件内容上限为 512,000 UTF-8 字节。

## 可选静态分析

基础能力不依赖额外安装。若运行环境已经安装 Ruff，可在启动前设置：

```powershell
$env:NOVACORE_RUFF_ENABLED = 'true'
```

Python 编译检查通过后，将额外检查未定义名称等 `F821`、`F822`、`F823` 问题。
Ruff 通过固定参数、隔离配置的子进程执行，不调用 Shell、不自动安装、不自动修复。
超时为 5 秒，标准输出和错误输出分别最多读取 64,000 字节，最多返回 20 条诊断。
检查器子进程只继承必要的系统环境，不继承模型密钥。

这些限制是应用层防线，不替代操作系统沙箱；文件可能在多步编辑期间暂时不合法。
