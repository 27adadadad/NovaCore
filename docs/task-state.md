# 面向模型的任务状态

任务状态不是终端底部的进度条，也不是长期记忆。它保存当前任务的有限运行事实，
帮助模型在多轮工具调用和上下文压缩后继续工作，不强制新增计划与执行阶段。

## 更新时机

- 用户提交任务后，记录目标；较长目标仅保留前 800 个字符，原请求仍在会话历史中。
- 一组工具结果全部保存后，记录最近工具的调用 ID、执行结果、校验结果和尝试次数。
- 状态发生变化时才在消息末尾追加快照，不改写已存在的消息；没有动态时间戳。
- 终止时区分 `response_returned`、`iteration_limit`、`cancelled` 和 `error`。
  返回答案不代表任务已经独立验证完成。

快照通过普通上下文消息传给模型，不改变 API 参数协议，不具有更高的指令优先级。
快照中的 `note` 明确说明这不是新的用户请求，并要求关注最新状态。
运行时只从带类型元数据的内部消息恢复状态，不把用户或模型写出的相似文本当作状态更新。

## 重复失败

对工具名与规范化参数计算指纹，不在状态里复制完整参数或工具输出。
同一任务内，连续三次相同操作失败后，继续提出相同操作会被执行层拦截。
修改参数或改用其他操作可尝试新路径；状态提示模型调整方法或请求用户帮助。
写入后的校验失败或检查器错误也计为失败尝试，但与文件写入结果分开记录。
这不是金额预算，也不保证模型一定选择正确的替代方案；总轮次上限仍然生效。

## 保存、恢复与压缩

快照使用独立的 JSONL 记录类型保存，可随会话恢复。`continue`、`resume`、`继续`、
`接着做` 保留已有目标，其他新请求会开始新的任务状态。
恢复旧版本会话时，没有快照就从本次请求建立状态。

上下文压缩不让摘要模型重建运行事实：旧快照从待摘要文本和近期消息中移除，
最新快照原样保留在压缩边界中。工具调用与整组结果之间不插入状态消息。
如果取消发生在工具调用尚未配齐结果时，不追加快照，以免进一步破坏消息配对。

## 边界

目前记录的是当前目标和最近执行事实，不是完整 TODO 管理器或所有文件的诊断总表。
最新文件校验通过不代表之前所有文件都正确。任务目标会随历史持久化，不应在任务中输入密钥。
持久追加有上下文开销；压缩前旧快照仍存在。稳定消息前缀不保证服务商缓存命中或费用下降。
已有 Bash 每次使用独立子进程，执行 `cd` 不会自动改变后续调用的起始目录；状态不伪造持久目录变化。
