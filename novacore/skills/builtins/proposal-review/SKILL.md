# 先提案，再独立审核

用于本地当前项目的受限候选修改，不是只读GitHub PR审查，也不是直接编辑原件。

1. 从用户请求确定具体需求和用户批准的1至5个现有文件；范围不清先询问，不自行扩展文件范围。
2. 调用 RunProposalReview，参数仅 task、allow_files。不要拼接Shell命令、运行CLI、读取密钥或通过Bash绕过授权。
3. 工具自动生成外部候选目录，展示需求、文件范围和最多10次额外模型请求；用户须在终端亲自输入RUN。本Skill或模型参数不能替用户授权。拒绝或非交互环境应停止，不自动换方式重试。
4. Proposer先读取/搜索/修改候选，按结构化诊断修正；Reviewer以独立上下文只读检查差异和候选。工具返回状态、补丁、报告与对话轨迹路径。
5. reviewed_no_findings只表示本轮未发现问题，不等于业务验收通过；awaiting_human_selection表示有问题需用户选择；inconclusive或失败需如实说明，不伪装成功，不自动重跑付费任务。
6. 向用户展示需求、实际结果、证据路径和限制。候选不会自动应用到原件，不自动提交、推送或合并。

当前只支持Git已提交的UTF-8普通非可执行文件，总计最多64KiB；允许文件有未提交改动时停止，避免忽略用户工作。只做语法/JSON检查，不执行项目代码或任意命令。双Agent每个最多5轮、共享最多10次请求，主对话模型请求另计。
